# C++ SDK 使用指南

[English](guide.md) · [README](../README.md)

## 1. 安装与边界

SDK 与三个 CLI Demo 以 [MIT](../LICENSE) 许可在 [tansrai/tansr-cpp](https://github.com/tansrai/tansr-cpp) 提供源码。从 **[v0.1.0 正式发行](https://github.com/tansrai/tansr-cpp/releases/tag/v0.1.0)** 下载源码包、匹配平台的 SDK 或独立 Demo 包，并按同版校验清单核对摘要。二进制覆盖 Windows x64、Linux x64 和 macOS arm64；Conan/vcpkg 使用同版自有配方包，尚未进入社区公共索引。

库使用 C++17、CMake 3.25+，以下命令使用 Ninja。二进制 SDK 包解压后包含 `include/`、`lib/`、`dependencies/` 和 `share/TansrSDK/`；保留这个目录结构，只把 SDK 根目录传给 `CMAKE_PREFIX_PATH`，包配置会局部查找捆绑的依赖。二进制 SDK 消费不需要 Node、Go、Rust 或 SDK 源码。

在一个新的应用目录保存以下两个完整文件。这个最小程序核对公开 API、链接与 Runtime 启停，不发送网络请求；真实会话和认证接入见后文。

`CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.25)
project(my_app LANGUAGES CXX)
find_package(TansrSDK 0.1.0 EXACT CONFIG REQUIRED)
add_executable(my_app main.cpp)
target_compile_features(my_app PRIVATE cxx_std_17)
target_link_libraries(my_app PRIVATE tansr::sdk)
enable_testing()
add_test(NAME sdk_startup COMMAND my_app)
```

`main.cpp`：

```cpp
#include <chrono>
#include <iostream>
#include <tansr/crypto.hpp>
#include <tansr/json.hpp>
#include <tansr/runtime.hpp>

int main() {
    auto value = tansr::Json::parse("{\"decimal\":1.25}");
    if (!value || value.value().at("decimal").number_token() != "1.25")
        return 1;
    auto digest = tansr::crypto::sha256_hex("abc");
    if (!digest ||
        digest.value() != "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad")
        return 2;
    auto runtime = tansr::Runtime::create();
    if (!runtime)
        return 3;
    runtime.value()->stop();
    auto stopped = runtime.value()->shutdown(std::chrono::seconds(30));
    if (!stopped || stopped.value() != tansr::ShutdownStatus::stopped)
        return 4;
    std::cout << "Tansr SDK ready; no network request was made\n";
    return 0;
}
```

v0.1.0 二进制包提供 Release 静态 SDK；使用匹配的编译器/架构/CRT，在应用目录运行：

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/absolute/tansr-cpp-sdk-0.1.0
cmake --build build
ctest --test-dir build --output-on-failure
```

Windows 在 x64 Native Tools shell 中运行同样的命令，将前缀换成 `C:/absolute/tansr-cpp-sdk-0.1.0`；Release 保持 `/MD`。不要用这个 Release 制品配置 Debug `/MDd` 应用。

公共头位于 `include/tansr`，不暴露 curl/OpenSSL/JSON 私有句柄。Windows 默认 `/MD` 或 Debug `/MDd`；static/shared、Debug/Release、CRT 不得混配。PImpl 不意味着跨编译器、STL、版本 ABI 稳定。C++20 宿主可使用同一 C++17 API；首版不提供 C ABI、GUI 框架或任意 Shell。

v0.1.0 制品的平台基线如下；以对应制品清单的编译、依赖及最低系统标签为准。源码可重新编译不代表现成二进制兼容更老系统。

| 平台 | 构建与安装要求 |
|---|---|
| Windows x64 | VS 2022 / MSVC 19.44，Release `/MD`、Debug `/MDd`；使用 x64 Native Tools shell，部署时提供匹配的 MSVC 运行库 |
| Linux x64 | Ubuntu 24.04 / GCC 13 / glibc 2.39；最终二进制的 glibc/GLIBCXX 符号下限仍须按制品核验 |
| macOS arm64 | Apple 工具链；v0.1.0 制品的最低部署目标为 macOS 26.0，不宣称可在更低版本运行 |

从源码构建时仍须事先准备同配置的 curl 8.22.0、c-ares 1.34.8、OpenSSL 3.5.9，精确来源见 [dependencies.json](../packaging/dependencies.json)。源码默认 CMake 不下载依赖，生成操作目录已入库；源码安装与包配方见[配方](../packaging/README.md)。普通源码安装没有捆绑依赖时，将 SDK 与依赖前缀一并传给应用：

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="/absolute/tansr-cpp-0.1.0;/absolute/dependencies"
cmake --build build
```

宿主若已有匹配依赖，可显式加 `-DTansrSDK_NO_BUNDLED_DEPENDENCIES=ON`，同时提供自己的依赖前缀。该开关只禁用包配置自动选择 `dependencies/`，不会关闭依赖检查或保证任意版本 ABI 兼容。包配置中的依赖搜索不永久改变应用的前缀设置。

自行构建 Windows 共享库时，应用须能加载 SDK 和依赖的 DLL；部署相应 `bin` 目录及运行库，不能靠开发机全局 PATH 掩盖缺依赖。发行静态 SDK 已带开发依赖，仍须满足制品声明的 OS/CRT 运行条件。

三个 Demo 各有独立制品包，不是 SDK 链接目录。分别解包后，从各自的 `bin/` 调用对应程序；Windows 加 `.exe`。例如将 chat 包解压到 `/absolute/tansr-chat-0.1.0`，运行 `/absolute/tansr-chat-0.1.0/bin/tansr-chat --help`。它们与 Rust Demo 同名，不能覆盖已有安装，凭据与服务地址按下一节设置。

## 2. 认证、当前身份与私有文件

Serve 负责验证短期 token、应用配置和当前授权。SDK 不自动登录、不存长期 appkey。Demo 使用 `TANSR_TOKEN_FILE`（单行短期 token）和 `TANSR_SCOPE_FILE`（下列 UTF-8 JSON），二者必须在同一私有目录、不同文件：

```json
{"applicationScopeId":"app-demo","endUserId":"user-demo","authorizationRevision":"1"}
```

这些值必须来自开发者可信后端，且与 token 相符；Demo 文件本身不能授予 Serve 权限。每个请求重读 token，读前后核 scope；每次工具授权及档案访问也核 scope。刷新同主体 token 可以继续；改变应用、用户或授权修订会终止旧客户端操作，须创建新对象并按原资源对账。不会自动换用户重放写入。

文件和其直接目录须仅由当前用户访问；父路径不得含链接、Junction/reparse point，文件不得多硬链接。Unix 使用目录 0700、文件 0600，Windows 使用当前用户所有权及私有 DACL。SDK 拒绝不安全的已有路径，不替用户放宽或重写其 ACL。凭据通过共享只读句柄读取，chat/tools 可同时消费同一目录。

```sh
export TANSR_TOKEN_FILE=/absolute/private-credentials/token.txt
export TANSR_SCOPE_FILE=/absolute/private-credentials/scope.json
export TANSR_BASE_URL=https://serve.example.invalid
```

Windows PowerShell 对应设置（这里只保存文件路径和服务地址）：

```powershell
$env:TANSR_TOKEN_FILE = 'C:/absolute/private-credentials/token.txt'
$env:TANSR_SCOPE_FILE = 'C:/absolute/private-credentials/scope.json'
$env:TANSR_BASE_URL = 'https://serve.example.invalid'
& 'C:/absolute/tansr-chat-0.1.0/bin/tansr-chat.exe' --help
& 'C:/absolute/tansr-tools-0.1.0/bin/tansr-tools.exe' --help
& 'C:/absolute/tansr-archive-0.1.0/bin/tansr-archive.exe' --help
```

Unix 用各自安装前缀下的 `bin/tansr-chat`、`bin/tansr-tools`、`bin/tansr-archive`；后文命令名均指该安装位置。凭据文件须事先由可信宿主写入，环境变量不是 token 内容。

ApiClient 接受不含凭据、路径、query 或 fragment 的 HTTP(S) origin；当前实现不按回环/非回环限制 HTTP。建议仅在回环开发使用明文，实际部署使用有效 HTTPS。系统信任与企业 CA 由 `RuntimeOptions.ca_file` 配置，不关闭主机名或链验证。Demo 不把 token 放入命令行、日志、错误 detail 或档案。网络错误仅显示安全错误码；显式诊断 `Error.detail` 可能含业务/服务端内容，宿主须单独保护。

## 3. Runtime 与回调生命周期

宿主持有 Runtime 最终所有权；ApiClient、Session 和执行器共享该底座。停止顺序是取消应用工作、退出并 join 应用 worker、调用客户端 shutdown、Runtime stop/shutdown，直到 `ShutdownStatus::stopped` 后才销毁。`pending` 是尚未静止，不是成功。不要在 SDK callback 中等待自己、释放最后一个 Runtime 或卸载 DLL；callback 可以发出取消/stop 请求。

```cpp
#include <tansr/api.hpp>
#include <tansr/session.hpp>

void connect(std::string base, tansr::TokenProvider provider) {
    auto runtime = tansr::Runtime::create();
    if (!runtime) return;
    tansr::ClientOptions options;
    options.base_url = std::move(base);
    options.token_provider = std::move(provider);
    auto api = tansr::ApiClient::create(std::move(options), runtime.value());
    if (api) {
        auto sessions = tansr::session::SessionClient::create(api.value());
        // 使用显式 Result 检查，业务代码在此消费 sessions。
        api.value()->shutdown();
    }
    runtime.value()->stop();
    auto stopped = runtime.value()->shutdown(std::chrono::seconds(30));
    // 宿主应在此处理错误/pending，并保留仍被工作引用的 Runtime。
    (void)stopped;
}
```

`CancellationToken` 只取消本地请求/观察，不自动调用 Serve interrupt、close 或 ACK。网络字节、Json、事件和 Result 拥有存储；不要将临时引用捕获到生命周期之外。业务 handler 应合作观察 cancellation；SDK 不安全强杀 C++ 线程。

## 4. 会话 Demo

```sh
tansr-chat --base http://127.0.0.1:8787 --message "你好"
tansr-chat --family sdk2-offload-v1 --prepare-create /absolute/intents/session.json --request-id app-create-001
tansr-chat --family sdk2-offload-v1 --create-intent /absolute/intents/session.json
tansr-chat --attach SESSION_ID
tansr-chat --resume SESSION_ID --last-event-id 42
```

默认 `sdk1`；新族必须明确 `--family sdk2-offload-v1`。新族创建的 `--request-id` 由调用者保存；失回后保留原意图，不生成新 ID 重建。`--attach` 连接已有 live 会话，`--resume` 使用原恢复入口，两者不能互换或同时提供。给活动轮发送 `--message` 会拒绝，不能悄悄新开轮。

推荐按上面两步创建 offload 会话：`--prepare-create` 在同一个私有文件内原子保存原 `requestId`、可选 `--model`、完整创建 body、传输请求键、绝对截止时间及 base/family/当前授权归属，不发送请求；`--timeout` 决定准备时的意图有效期。`--create-intent` 读取原值调用公开 `SessionClient::create`，成功只输出 `session:`，不会启动或重发业务轮。随后使用同族 `--attach SESSION_ID` 对话。发生创建失回时在原截止时间内重跑同一 `--create-intent` 命令，不重新准备、不换键、不延长截止。SDK2 的会话创建会由 Serve 自动建立 Source/binding；恢复原会话创建也恢复该归属，不伪造手动 binding epoch。

两个意图命令不接受 `--message`、`--last-event-id`、`--resume`、`--attach`，恢复还禁止覆盖 `--model` 或 `--request-id`。已有文件、非法格式、过期、跨 origin/family/应用/用户/授权修订均失败；原文件保留供对账。原直接 `--request-id` 创建方式仍可用，但要求应用自行可靠保存完整意图，不能仅凭同一 ID 声称请求 body 和截止时间已保全。

流在发送前打开，`TurnTracker` 从发送前 seq 与实际 turnId 识别本轮终态。202、EOF、旧轮完成或 session.ended 都不代表本轮完成。每个新轮创建新 tracker。`--last-event-id` 是处理游标，不能拿档案 ACK、水位或历史代际替代；发生 gap 必须对账，Demo 不自动跨缺口前移。

交互命令：

| 命令 | 行为 |
|---|---|
| `/interrupt` | 显式请求远端中断，继续等待实际终态 |
| `/allow TICKET`、`/deny TICKET` | 仅回答当前实收、未关闭票据及原 digest，默认不批准 |
| `/answers TICKET JSON_ARRAY` | 回答实收问题；每项含 questionId、selectedOptionIds 和可选 freeText |
| `/target` | 查询当前同轮输入目标及能力 |
| `/insert JSON_OBJECT` | 明确 inputId、target.historyEpoch/turnId、content.text、可选 ack；不替换当前轮 |
| `/history` | 读取 history(0,0) 计数视图，0 是合法 limit |
| `/quit` 或 Ctrl+C | 停止本地观察，不宣称 Serve 已停止 |

```text
/insert {"inputId":"input-001","target":{"historyEpoch":"原值","turnId":"原值"},"content":{"text":"补充要求"},"ack":"memory"}
```

请求 durable 但服务不支持时原样失败，不降级为 memory。accepted/received 不等于 consumed。`--message` 非交互遇审批/问答会非零退出，并保留 session 供交互接续；不自动同意。

先执行 `/target` 取得当前原始目标，再填写 `/insert`，不要把示意中的“原值”当作实际 ID。控制命令回执会立即刷新到标准输出，即使模型正在等待也可由管道宿主读取。`/interrupt` 收到受理后仍等待真正的 `turn.aborted`；本 Demo 对中断轮非零退出，不显示 `[turn completed]`。`/quit` 只结束本地观察，原活动轮仍可重新 attach。

SDK 还提供 `send_blocks`（TextBlock/ImageBlock）、`transcribe`、`speak`、checkpoints/checkpoint/restore/export/import/delete、compact、cwd 和 application_prompt_meta。调用 STT/TTS 不等于录音/播放器或主模型原生音视频块。平台、Serve 与请求配置的系统提示词合成由核心控制，C++ 不额外拼接覆盖；应用应读原 meta/配置能力了解当前实际策略。

## 5. 显式终端业务工具

```sh
tansr-tools --journal /absolute/private-journal --require-output
# 另一个终端使用上条输出的会话 ID
tansr-chat --attach SESSION_ID
```

Serve 应用策略须允许 `DemoOrderStatus`；示例注册一个只读合成订单函数，不装 Shell、文件工具或任意执行器。注册→initialize→首次 bind→可选 output 协商→Runner 完整消费公开 SDK。询问“查询订单 DEMO-001”后输出第一块 stdout、750ms 合成等待、stderr，再由 Runner 封 seal。`capture` 只说明采集，output ACK/seal 与业务回执分开；任何输出失败都不能重跑业务 handler。

`--run-once` 处理一个排队 operation 并退出，适合联调；默认持续领取且续租，Ctrl+C 合作取消。FileJournal 是私有明文事实账本，保存原操作认领和确定回执，不是加密档案。只有能证明零副作用才能返回 `ToolFailure::rejected`，异常、不能确定的取消或输出失回是 unknown。业务 `{status:"error"}` 可以是已确定的业务结果。

Demo 授权器每次读当前 scope，核 app/user/revision/session/binding/workspace/tool。生产应用仍须接入实时撤权与资源政策；不能把注册平台当成权限或设备失败后回落 Serve 宿主。

## 6. 本地档案与材料

Source/provider 由 Serve 宿主事先登记；Demo 不发明注册 URL。使用独立目录存档案和意图。设置 `TANSR_ARCHIVE_KEY_FILE` 为私有的 64 位十六进制 AES-256 密钥文件；一 key 只供一个档案，`--key-id` 由宿主管理。密钥不放档案旁边、不在解密失败时自动更换；密钥轮换使用 FileStore 显式 API。

```sh
tansr-archive --mode prepare-create --session SESSION --source SOURCE --request-id bind-001 --intent /absolute/intents/create.json
tansr-archive --mode create --intent /absolute/intents/create.json
tansr-archive --mode creation-status --intent /absolute/intents/create.json
tansr-archive --mode sync --binding BINDING --file /absolute/archive/history.bin --key-id local-key-1
tansr-archive --mode status --binding BINDING
tansr-archive --mode recover --binding BINDING --file /absolute/archive/history.bin --key-id local-key-1 --request-id recover-001
tansr-archive --mode materials --binding BINDING --file /absolute/archive/history.bin --key-id local-key-1 --request-id response-001 --intent /absolute/materials/response.json
tansr-archive --mode material-status --intent /absolute/materials/response.json
```

每条命令都携原 `--family`、同 Base URL 和 scope；意图旁的 `.owner` 文件拒绝改族/身份重放。prepare-create 先持久保存原 body/requestId/epoch/绝对截止才允许 create；prepare 不创建 binding。截止到期不能改时间或换键；使用 status 对原操作查账。已有意图绝不覆盖，文件只写入一半时保留现场，不把失败打印成功。

FileStore 核页链、记录/正文/附件摘要及当前身份，整页+附件+pending ACK 原子耐久后才发送 ACK。sync 的 complete、recover 的已确认原 pending、水位 coverage 和材料消费是不同事实。recover 只处理原 pending/明确 stale 的显式恢复，不替代完整同步；一般 412、撤权和已过期 epoch 不自动 rebase。

materials 只订阅当前 request，把首次收到的 remaining TTL 固定为绝对截止，并保存 `.request` 原意图；只回供点名且已验证记录。准备/分块/等待都不续期，最终 response 落盘后 submit。失回用原 response 的 `material-submit` 或 `material-status` 对账；received 不宣称 core-consumed。材料、档案、执行日志不成为第二套上下文、审批或计费权威，也不代表记忆全本地化、多副本备份或跨 SDK 私有介质兼容。

## 7. 状态、故障与交付

`Result<T>` 必须检查；未确认结果保留原 ID/请求/截止/介质。`ApiClient::retry_same_request` 仅在原错误允许且同请求见证一致时使用，不作为通用自动重试。默认错误日志不输出 raw detail、token、工具参数或正文。

Serve 必须提供 UAPI revision 7、所选 family 和实际启用的操作。能力关闭、当前授权不足或合同指纹不符时，应处理拒绝，不能切换 family 或重建操作规避。工具输出、offload 与档案材料须按对应能力协商；本指南不以某个 Serve 版本号替代这些检查。

公开开发使用 `python tools/contract_check.py --mode public`，核对分发声明中的 20 份原字节资产；内部 39 项参考与私有历史不随公开源码分发。[主线 CI](https://github.com/tansrai/tansr-cpp/actions) 和 [v0.1.0 发行记录](https://github.com/tansrai/tansr-cpp/releases/tag/v0.1.0)分别提供验证与制品入口。按发行记录核对三 OS 原生、真实 Serve、安装消费的证据及限制；本指南或 `--help` 成功不替代这些证据。第三方依赖许可见 [NOTICE](../packaging/NOTICE.md)。
